## Часть B — Структура

### B.1 Пакетная раскладка `satanbonchbot/`

**Проблема:** в корне репозитория ~20 `.py`-модулей вперемешку с
конфигами (`Dockerfile`, `pytest.ini`, `ruff.toml`, `requirements*.txt`,
`.env.example` …). Открыв репозиторий, видишь «свалку» файлов — это и есть
главное «стыдно показать». Код хорошо разложен по слоям *логически*
(`ARCHITECTURE.md`), но не *физически*.

**Что сделать:** собрать прикладные модули в пакет `satanbonchbot/`:
```
satanbonchbot/
    __init__.py
    __main__.py          # точка входа (бывш. main.py)
    config.py  db.py  security.py  ...
    handlers/  (как есть)
tests/        (как есть, импорт — from satanbonchbot import ...)
assets/  scripts/  docs/
```
- Все 20 модулей + `handlers/` → в пакет `satanbonchbot/`.
- Внутренние импорты: `import config` → `from satanbonchbot import config`
  (или относительные — решить при выполнении, единообразно).
- Убрать костыли `try/except ImportError` с `sys.path.insert` (нужны были
  при плоской раскладке) — в пакете импорты работают штатно.
- `Dockerfile`: `CMD ["python", "-m", "satanbonchbot"]`.
- `conftest.py` остаётся в корне; `tests/` импортируют из пакета.
- `ARCHITECTURE.md` и `plans/` → в `docs/` (корень чище); поправить ссылки.
- Рантайм-файлы (`users.db`, `timetable.json`) — остаются в рабочей
  директории (volume-монтирование Docker), не в пакете.

**Решение по раскладке.** Берём пакет в корне (`satanbonchbot/`), а не
`src/satanbonchbot/`: `src/`-layout нужен библиотекам (защита от импорта
неустановленного пакета), а здесь — деплоимое приложение, `python -m
satanbonchbot` проще и привычнее. Зафиксировать при выполнении.

**Риск:** средний — трогает каждый импорт, `Dockerfile`, `conftest`,
`healthcheck.py`. Чисто механически, но широко. Под защитой 452 тестов:
после переноса весь `pytest` обязан быть зелёным. Делать одним заходом,
аккуратно; сверяться `python -c "import satanbonchbot"` и
`docker compose build`.

**Проверка:** `pytest` зелёный; `docker compose up` собирается и
запускается; корень репозитория — только пакет, `tests/`, `assets/`,
`scripts/`, `docs/`, конфиги и README/LICENSE.

### B.2 `pyproject.toml`

**Проблема:** конфигурация проекта разбросана: `requirements.txt`,
`requirements-dev.txt`, `ruff.toml`, `pytest.ini`. Современный стандарт —
единый `pyproject.toml`.

**Что сделать:**
- `pyproject.toml` с `[project]` (имя, версия, описание, Python-требование,
  автор) и `[project.scripts]` (точка входа).
- Перенести конфиг `ruff` (`ruff.toml` → `[tool.ruff]`) и `pytest`
  (`pytest.ini` → `[tool.pytest.ini_options]`), старые файлы удалить.
- **Решить при выполнении:** переносить ли зависимости в
  `[project.dependencies]` (тогда `Dockerfile` ставит `pip install .`) или
  оставить `requirements*.txt` как есть. Версии запинены ради
  воспроизводимого Docker-образа — пиннинг сохранить в любом случае.

**Риск:** низкий — конфиг-файлы; проверяется прогоном `ruff`/`pytest`.

**Проверка:** `ruff check .` и `pytest` читают конфиг из `pyproject.toml`;
сборка Docker работает.

## Часть C — Качество

### C.1 CI на GitHub Actions

**Пересмотр прежнего решения.** Планы v2–v5 отказывались от CI с пометкой
«деплой через Coolify». Но **CI ≠ CD**: GitHub Actions здесь — не деплой, а
прогон `pytest` + `ruff check` на каждый push/PR. Для «витрины» зелёный
бейдж CI — сильный сигнал качества; деплой остаётся за Coolify.

**Что сделать:**
- `.github/workflows/ci.yml`: на push/PR — установка зависимостей,
  `ruff check .`, `pytest`.
- Бейдж статуса CI в README (A.3).

**Риск:** низкий — не трогает рантайм. Деплой не затрагивается.

**Проверка:** workflow зелёный на `main`; бейдж в README отражает статус.

### C.2 Убрать фасад-реэкспорты `main.py`

**Проблема (архитектурная чистота):** `main.py` реэкспортит публичные
имена перенесённых модулей (`from config import *`, `from db import …` и
т.п.) ради обратной совместимости обращений `main.X` и тестов. Это
единственный заметный архитектурный «шов»: открыв `main.py`, видишь десяток
`import *`. Для «красивой архитектуры» — кандидат на удаление.

**Что сделать:** убрать реэкспорты; обращения `main.X` (в основном в
тестах) перенаправить на реальные модули (`from satanbonchbot import db` →
`db.X`). `main.py`/`__main__.py` остаётся тонким оркестратором без
`import *`.

**Риск:** средний — много правок в тестах (`main.X` → модуль). Не影ляет на
рантайм-поведение. Делать последним, под защитой тестов; **опционально** —
если фаза рвётся по времени, переносится в v7 (репозиторий «красив» и без
этого; шов задокументирован).

**Проверка:** в `main.py`/`__main__.py` нет `import *`-реэкспортов;
`pytest` зелёный.


**Логика порядка:**
- A.1/A.2 — быстрые, изолированные; артефакты в git стыдно показать прямо
  сейчас — первыми.

- C.1 — CI; бейдж нужен в README.

  бейдж CI.
